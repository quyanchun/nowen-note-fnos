# 飞牛 fnOS 部署与 AI 接手说明

本指南适用于本仓库 v1.5.4。应用包内部仍使用 `nowen-note-private` 标识和 `/app/nowen-note-private/` 前缀，便于已有实例继续使用原数据与入口。

## 1. 部署前确认

- 确认 NAS 的 CPU 架构（`uname -m`）：x86_64 对应 `linux/amd64`，aarch64 对应 `linux/arm64`。
- NAS 已安装并启动 Docker，具备应用中心手动安装权限。
- 在可信的开发机或 NAS 构建当前源码镜像，准备飞牛官方 `fnpack` 工具。工具来源见[飞牛开发文档](https://developer.fnnas.com/)。
- 已有实例先确认实际数据挂载、应用标识与端口；不要通过清空数据库、目录或同步队列来更新。
- 地址、账号、密码、SSH 密钥与模型 Token 由部署者自行提供。只保存在本机安全存储或 Git 忽略的配置文件中。

## 2. 镜像与应用包

```bash
VERSION=1.5.4
# ARM64 设备将平台改为 linux/arm64。
docker buildx build --platform linux/amd64 --load \
  -t "local/nowen-note-fnos:$VERSION" .
docker save "local/nowen-note-fnos:$VERSION" | gzip > "nowen-note-fnos-$VERSION-image.tar.gz"
python3 scripts/fpk/build-private-fpk.py \
  --fnpack /path/to/fnpack \
  --image "local/nowen-note-fnos:$VERSION"
```

FPK 输出到 `dist-fpk-private/`。镜像名必须与 FPK 中的镜像一致；FPK 不包含 Docker 镜像，也不会自动从仓库构建镜像。

将两项产物传到 NAS 后，在 NAS 执行：

```bash
gzip -dc nowen-note-fnos-1.5.4-image.tar.gz | sudo docker load
```

在飞牛「应用中心 → 手动安装」选择生成的 FPK。按系统要求确认安装声明，启动应用，并在应用权限中允许需要使用的用户。应用由独立应用用户运行，不需要把系统 Docker Socket 挂进笔记容器。

首次独立登录的管理员密码由实例随机生成，保存在数据目录的 `.initial_admin_password`，权限为仅拥有者可读。管理员可在 NAS 本机受限终端查看；不要把它贴到 README、Issue 或共享日志。已有数据库的账户与密码保持不变。

## 3. 访问方式

### 飞牛应用网关

从飞牛桌面打开，或使用自己的 NAS 根地址加 `/app/nowen-note-private/`。飞牛会话由系统网关校验，笔记再关联对应 NAS 身份。没有飞牛会话时，网关可能在应用页面加载前直接拒绝访问；笔记 Token 不会替代飞牛网关登录。

桌面客户端在同步设置中选择 NAS 网关方式，填写自己的 NAS 地址并授权。只复用该 NAS 的现有会话，不向其他域名转发凭据。

### 独立笔记服务

FPK 默认将附加网页端口 3504 绑定到 `127.0.0.1`。可让自己的 HTTPS 反向代理指向该地址，通过独立的笔记域名访问统一登录页与单 Token 收集 API。使用 NAS 已有的代理管理方式，不直接改飞牛系统 Nginx。

需要局域网直连时，打包时用 `--web-bind` 显式指定 NAS 的局域网 IPv4 地址，可用 `--web-port` 修改端口。不要填写维护者的地址；不要把无认证 HTTP 暴露到公网。

网页设置的「NAS 登录」页面可添加独立笔记网页与飞牛门户的一对地址。也可在打包时通过 `--web-origin` 与 `--portal-origin` 一起指定自己的 HTTP/HTTPS 根地址；默认留空，不包含共享的地址或凭据。这是回调地址配置，不包含模型服务配置。

## 4. AI、剪贴板和分享

1. 登录后在 AI 设置里填写自己的模型渠道、Key 和可选 Headers，分别选择对话、Embedding、语音和多模态模型。
2. 剪贴板设置里选择连接方式、配置过滤与整理规则，并复制自己的地址和收集 Token。
3. 独立笔记服务可只用地址与 Token；走飞牛 `/app/` 则还需客户端拥有飞牛登录会话。
4. 图片可由多模态模型生成说明，实际文件存入附件目录。服务端日志提供删除、强制收集和撤销；缺少完整原文的旧日志不能凭预览重建内容。
5. 若使用公开分享域名，应指向同一实例，并在设置里配置自己的分享来源地址。

## 5. 验收清单

- 检查容器健康与应用中心运行状态，记录实际镜像和版本。
- 分别验证飞牛登录、独立账号登录和退出后访问边界。
- 创建测试目录与笔记，刷新重开确认保存；桌面连接后确认正文与附件实际可读。
- 用合成内容验证收集过滤、强制收集、归档路径、同类追加与撤销；不要拿真实密码做测试。
- 验证图片保存与预览、失败日志的具体原因、跨账号访问拒绝。
- 不把“HTTP 200”“队列为空”或“安装完成”作为全部验收通过的替代。

## 6. 更新已有开发部署

[快速部署脚本](./dev-deploy.md)可从最新源码更新已经安装好的 NAS 和 Mac，不重装 FPK、不清空用户数据。它需要部署者自己的本机配置，并会在运行环境或依赖不兼容时停止，要求先执行完整打包。

如果此前更改过 Electron 运行代码或后端依赖，需要完整重打对应运行包。任何系统安全提示、钥匙串确认和飞牛安装声明，由部署者按系统要求处理。

## 交给 AI

直接把本仓库与 README 中的部署提示词交给 AI 即可开始。AI 应先阅读 `AGENTS.md`，确认当前环境、架构和权限，再逐项实施与验收；缺少连接方式时向部署者索取，不推测账号密码，不复用其他人的配置。
